# סט בדיקות חוזר — Word Steps Grade 8

## הפעלה

מתיקיית האפליקציה, לאחר התקנת Node.js:

```text
npm ci
npm test
```

הפקודה מפעילה את קוד האפליקציה האמיתי בסביבת jsdom מבודדת. היא אינה משנה את האתר או את נתוני הלומדים. קוד יציאה 1 פירושו שקיימות בדיקות נכשלות — אין לשנות ציפיות רק כדי לקבל דוח ירוק.

בדיקת האתר החי, עם 17 בקשות GET בלבד ובמקביליות מרבית של שלוש:

```text
npm run test:live
```

אפשר לבדוק כתובת חלופית באמצעות `node tests/live-smoke.cjs https://example.com`. בדיקה זו קוראת קבצים ציבוריים בלבד. היא אינה בדיקת עומס או אישור לקיבולת משתמשים.

תצוגה מקומית לבדיקות ידניות ודפדפן:

```text
npm run test:serve
```

פתחו `http://127.0.0.1:52189/`. השתמשו בפרופיל בדיקה נפרד; בדיקות ידניות של ייבוא ואיפוס משנות את הנתונים באותו דפדפן. Ctrl+C סוגר את השרת המקומי.

## הקבצים והתוצרים

- `app.test.cjs`: תוכן, ארבעה מצבי לימוד, ציורים, שמע, סינון, בדיקת תשובות, רשימת חיזוק, ייבוא, שחזור, שמירה ובידוד בין לומדים.
- `delivery.test.cjs`: תצורת הפצה, קבצים נדרשים, תקציבי גודל וזמן, סימון נגישות ומובייל וסריקה בסיסית למניעת הפצת מפתחות.
- `live-smoke.cjs`: בדיקת HTTP אמיתית של חמשת משאבי האתר וקריאות מקבילות מוגבלות.
- `browser-smoke.mjs`: תרחיש דפדפן חוזר להפעלה ב־Codex דרך כלי CUA בלבד. הבודק מקבל ידית Tab לאתר וידית capability בשם viewport, ומפעיל `runBrowserSmoke({tab,viewport,outputDirectory})`. יש לקרוא תחילה את תיעוד CUA ואת תיעוד viewport. הבדיקה מצלמת רוחבים 360, 390, 768 ו־1280, בודקת היעדר גלילה אופקית, עוברת על 58 איורים ומצבי הלימוד. היא אינה שולחת תשובות או מאפסת נתונים. לא מפעילים קובץ זה ב־Node רגיל או ב־Playwright חיצוני במקום CUA.
- `MANUAL-TESTS.md`: בדיקות UI/UX, נגישות, משתמשים אמיתיים, מכשירים וביצועים ידניות.
- `reports/latest.tap`: תוצאה מלאה ניתנת לאבחון.
- `reports/latest.json`, `reports/LATEST.md`: סיכום ההרצה האחרונה.
- `reports/live-smoke.json`: זמני תגובה וסטטוס האתר החי.
- `reports/browser/`: תוצאות דפדפן וצילומי מסך, אם הורץ תרחיש CUA.
- `FINDINGS.md`: ממצאים, מגבלות ובדיקות שטרם בוצעו.

## מה פירוש ״באקאנד״ כאן

זו אפליקציה סטטית: אין API עסקי, בסיס נתונים, רישום משתמשים או חשבונות לומדים. לכן בדיקות CRUD, סיסמאות, הרשאות תפקידים וטרנזקציות הן **לא ישימות למוצר הנוכחי**. האחסון בדפדפן נבדק בבדיקות האפליקציה; האירוח נבדק באמצעות HTTP. אין גישה לתשתית הפנימית של ספק האירוח ולכן אין כאן בדיקת שרתים פנימיים או חדירות לספק. אם יתווסף שרת, חובה להוסיף בדיקות API, אימות, הרשאה, בידוד נתונים ותחרות על רשומות לפני פרסום.

## שער שחרור

1. הריצו `npm test`; תעדו כל כשל ושמרו קישור לממצא. שני כשלים קיימים מתועדים ב־FINDINGS.md.
2. הריצו את בדיקת הדפדפן ואת רשימת בדיקות המכשירים לאחר שינוי מסכים או שמע.
3. הריצו בדיקת HTTP לאחר פרסום ואמתו שאין מסך התחברות.
4. לפני שימוש כיתתי נרחב, בצעו בדיקות משתמשים ומכשירים אמיתיים. אל תסיקו קיבולת מ־12 בקשות GET.
5. אל תפרסמו את תיקיית הבדיקות או node_modules לאתר. אין צורך לפרסם גרסה חדשה רק עקב שינוי בבדיקות.

## עקביות ותלות בסביבה

הבדיקות משתמשות בנתונים מבודדים. שמע ואישור חלוניות מדומים בבדיקות jsdom; שמיעת קול, מגע, הורדת קבצים וקורא מסך דורשים בדיקה במכשיר אמיתי. סדר בחירות התשובה אקראי ולכן נבדקים התוכן והתוצאה, לא מיקום כפתור. ספי הזמן המקומיים הם אמצעי רגרסיה נדיב, אינם מדדי חוויית משתמש. זמן רשת וקאש נמדדים בנפרד. קובץ package-lock.json מקבע את גרסאות התלויות להרצה חוזרת.
